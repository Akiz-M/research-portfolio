Contributing to AKIZ M

1. Purpose

AKIZ M welcomes constructive contributions to independent scientific research, software engineering, artificial intelligence, computational science, and technology development.

Our objective is to maintain technically sound, transparent, reproducible, and responsibly developed projects.

2. Core Principles

Every contribution should respect:

- Scientific integrity
- Technical accuracy
- Reproducibility
- Transparent documentation
- Responsible innovation
- Respectful collaboration
- Intellectual property rights

3. Contribution Workflow

1. Identify an existing issue or propose a new improvement.
2. Understand the project's objectives and architecture.
3. Discuss significant changes before implementation.
4. Submit focused and clearly documented changes.
5. Provide appropriate tests or supporting evidence.
6. Request review before merging.

4. Code Quality

Contributions should:

- Use clear and descriptive names.
- Follow established language conventions.
- Avoid unnecessary dependencies.
- Include appropriate error handling.
- Provide tests for important functionality.
- Document installation and usage requirements.

5. Scientific Research Standards

Research-related contributions should distinguish between:

- Observed results
- Independently reproduced results
- Hypotheses
- Proposed methods
- Limitations
- Unverified claims

Experimental results should include relevant methodology, dataset information, evaluation metrics, and reproducibility details where applicable.

6. Data and Security

Contributors must not publish:

- Passwords or access tokens
- Private personal information
- Confidential research data
- Unauthorized copyrighted material

Security vulnerabilities should be reported privately through an appropriate security reporting channel rather than publicly exposing exploit details.

7. Pull Request Expectations

Every pull request should explain:

- What changed?
- Why was the change necessary?
- How was it tested?
- What evidence supports the change?
- Are there known limitations?

Keep changes focused and avoid unrelated modifications.

8. Review and Acceptance

All contributions are subject to review.

Submission does not guarantee acceptance or inclusion in an official research project.

Maintainers may request additional evidence, testing, documentation, or revisions.

9. Responsible Collaboration

All participants are expected to communicate professionally, respect different perspectives, and contribute constructively.
